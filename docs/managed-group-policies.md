# 分组消息处理与文本替换（本地第一版，未部署）

继续使用提示词注入管理界面，规则增加四种操作：`append`（旧规则默认）、`replace_system`、`replace_input`、`replace_output`。新增规则仍需管理员保存；已有配置不会自动开启替换。

## 语义

- 替换 System 删除客户端请求的 System 消息，Responses 的 `instructions` 同时替换。保留 Developer、User、工具结构。客户端没有 System 时也会设置新 System；供应商和网关的协议内置指令不在“删除平台内置策略”的承诺范围内。
- 输入替换只修改 user 内容里的纯文本或 text/input_text 部件；图片、tool_result、工具参数不变。可勾选“整条替换”仅替换最新一条包含文本的用户消息，保留更早的对话历史和同条图片。
- 输出替换只改 assistant 正文（Chat `message.content`、Responses `output_text`、Anthropic text），不改 reasoning、工具名、参数、call_id、用量或实际模型字段。
- 文本替换是区分大小写的字面匹配，不是正则或语义改写。输出使用单遍、按规则优先级匹配，不递归替换新文字；输入多条规则按顺序执行。空替换文本表示删除，空匹配文本不允许。代码块或 JSON **文本内容**也可能被替换，应先使用本地预览检查。

## 协议范围与流式

支持已注册的 HTTP `/v1/chat/completions`、`/v1/responses`、`/v1/messages`、根路径 `/responses`、`/chat/completions` 和 Codex HTTP Responses 入口。用户提供的账号级旧注入规则继续在选号后匹配。原生 Gemini generateContent、音视频接口及 WebSocket 输出替换尚未覆盖，不能声称所有协议均支持。

HTTP 非流式 JSON 和 SSE 均处理。SSE 保留一个尚未发送的文本事件，暂存关键词尾部，实现相邻文本 delta 之间的跨片段匹配；在终止或工具事件前排空，不插入额外工具事件，不改调用 ID。`n>1` 在输出替换开启时拒绝，避免跨候选串字。工具事件、错误、用量不替换。不同文本部件之间不进行跨部件关键词匹配。

流式字段与最终 Responses 正文都处理，计费仍按上游原始 usage。超大事件/响应超过 2MiB 时输出处理转为透传；文本扩张、非流式路径数量和嵌套深度也有保护，避免小内存服务器因异常内容耗尽资源。因此第一版不是无条件保证任意大小内容全部替换。

## 可靠性与诊断

- 读取和写入缓存按互斥顺序协调，避免旧读取覆盖刚保存的规则。
- 读取失败使用最后有效配置，并节流刷新；没有有效配置时返回明确错误，不静默发未注入请求。
- 管理员手动刷新强制重读。保存携带版本，数据库比较原值后写入，跨进程并发冲突返回 409。
- 管理页“处理诊断记录”仅管理员可读，展示最近 100 条命中规则的记录或配置错误：request_id、分组 ID、配置版本、规则 ID、协议、入口处理前后字节数和处理状态。不为未匹配分组逐次写库。保留约 7 天，不存密钥、提示词正文或输出正文。写记录有短超时，失败不使模型调用失败。
- 诊断记录表示**入口处理/输出改写尝试**。另有 `transport_status`：通用 HTTP 上游发送前，利用独立 GetBody 副本核验注入文本是否仍存在（最多读取 128 KiB），不读取或修改正在发送的 Body。`text_presence_verified` 只证明文本存在，不证明角色、位置或模型遵循指令；`expected_text_not_found` 表示最终小请求未找到某条文本，也可能是后续规则覆盖，需结合规则顺序分析。大请求、无 GetBody、未经过通用 HTTP Transport、WebSocket 分别显示未核验或未观察状态，不能据此认定注入失败。不保存核验正文。
