# LaneAI 视频工作台

基于部署分支 `deploy/channel-quality-20261013`（`a8f6421`），新增单次视频生成与剧本分镜工作台，沿用本站登录、用户、分组、API Key、余额、审计和内容安全检查。

## 使用流程

用户后台 `/video-studio`：

- 单次：选择视频 Key/模型 → 设置画幅、清晰度、时长、声音 → 填写提示词、选择参考素材 → 确认费用 → 查看历史、播放与下载。
- 剧本：建立项目 → 选择聊天 Key 和模型拆分大纲（聊天调用单独计费）→ 编辑/增删/调整镜头顺序 → 设置全剧角色参考、本镜首帧/参考图、逐镜参考视频和音频 → 逐镜或整批生成。
- 单次生成与各镜头的参考素材独立；角色图、首帧与镜头图片合并去重后检查模型上限。批量报价前先检查全部镜头的时长、素材数量和合并提示词长度，切换模型不静默删除现有素材。
- 项目与所选视频密钥、模型、清晰度、画幅和声音设置自动保存到服务器，支持版本冲突检测、本地草稿恢复、JSON 导入/导出、归档。重新生成会保留旧任务的历史记录。
- 素材存储在本站 PostgreSQL，单文件上限 30MB、每用户总量 200MB；上游通过含 192 位随机 ID 的只读 HTTPS 地址读取。不要把素材地址当成可公开分享的文件列表。引用中的素材不能删除。
- 模型和素材等初始请求独立加载，部分失败不阻止历史轮询；任务结算时刷新余额。导入先检查完整文件结构，再作为新项目保存，清除旧任务身份。
- 视频输出使用上游返回的外链，按上游保留期限提供播放/下载；目前不把输出视频永久复制到本站。剧本导出包含已生成镜头链接，不是自动剪辑或合并视频。

## 管理员配置

1. 添加 **视频 → API Key → LaneAI 异步任务（laneai_task）** 上游账号，Base URL 为 `https://laneai.dev/v1`，密钥只填后台账号中。禁止写进源码或前端。
2. 创建独立的 **视频标准余额分组**。保存视频渠道配置时自动绑定所选账号，不需要图片生成开关。订阅分组暂不承接此适配。
3. 在视频工作台“渠道与计费”中选择视频分组、视频上游账号、本站 HTTPS 根地址和最大上游并发（1–8）。
4. 点击“读取上游模型与成本”：通过该账号的 `/v1/models` 过滤可用模型，再读取 `/api/models` 中的 `video_rates`、时长与素材能力。不会使用错误的通用 `price_yuan`。读取不会自动保存、不会开放渠道；相同单位的现有售价与高级规则保留，新项按成本预填，必须人工复核利润。高级规则成本需要手动复核。

   核对模型 ID、时长、分辨率、素材能力。按秒模型与按条模型分别配置，不能合并为同一售价。
5. 设置**最终站内余额售价**及**人民币上游成本**，再开放分组。这里的最终售价不叠加聊天分组倍率/高峰倍率。模板数字只是上游公开价参考，不代表适合本站的售价。
6. 用户创建密钥时选择第五类“视频”，再选择对应视频分组；如启用模型白名单，加入准确调用名。

LaneAI 当前公开配置参考（需定期自行核对）：

| 模型 ID | 收费方式 | 上游人民币成本参考 | 上限 |
| --- | --- | --- | --- |
| `MiniMax-H3` | 按秒 | 768P ¥0.22/s；2K ¥0.35/s | 30s |
| `MiniMax-H3 2K` | 按条 | ¥2.20/条 | 1–15s，2K |
| `MiniMax-H3 768P` | 按条 | ¥1.50/条 | 1–15s，768P |

以上成本根据该站“充值人民币 ¥1，站内显示 $1”换算，不是真实美元。当前按秒 H3 最短 4s，按条模型最短 1s；以读取上游目录得到的实际配置为准。输入素材是否另收费应先向上游确认。

## 独立分类与扩展定价

- `accounts.platform` 和 `groups.platform` 使用独立 `video` 值，账号凭据 `api_protocol=laneai_task`。当前仅适配 LaneAI；不能把其他视频供应商只改域名就当兼容。
- 视频 Key 被公共认证层限制在视频任务、素材、模型和文档端点，不能误入聊天/生图网关。原有四类密钥分类之外新增“视频”。
- 可动态添加/移除模型，配置 480p/720p/768p/1080p/2k/4k、按秒/按条和能力范围。能力值必须符合实际上游。
- 基础价格使用 `mode` 和每个清晰度的 `rates`。可选 `rules` 是互斥条件价格表：按 `resolution`、`min_seconds/max_seconds`、`audio=any/on/off`、`reference=any/with/without` 匹配。
- 非空规则替代基础价，每次必须恰好命中一条。规则保存时拒绝重叠，未配置组合拒绝生成。`mode=second/job`，`rate` 为售价，`cost_cny` 为成本；`minimum_seconds` 起计秒数、`step_seconds` 向上取整。
- `base_fee` 为任务固定附加费；`image_fee/video_fee/audio_fee` 按输入素材数量收费。对应 `*_cost_cny` 记录人民币成本，不向普通用户公开。
- 请求可预先确定的价格才支持确定报价。参考视频/音频的时长计费、Token/算力用量或上游返回的实际用量收费未实现自动测量与结算，不能通过填写一个单价冒充支持。遇到新结构必须先适配、验证再开放。
- 尚未发布的旧版曾复用 OpenAI 分组；升级开发预览环境需新建视频账号和分组并重新绑定渠道，不能把现有聊天分组整体改成视频。未结算旧任务应先完成核对。

## 用户接入文档

- 视频工作台新增“API 调用说明”，视频密钥的“使用说明”展示视频专用示例。
- `GET /v1/skills` 与 `GET /v1/skills/guide` 需本站视频 Key，返回当前 Key 可用模型、已脱敏售价规则、能力、错误码和协议说明。没有余额时也能读取文档和任务结果。
- `GET /v1/models` 对视频 Key 返回该视频渠道的模型列表，不混入聊天默认模型。
- `POST /v1/video/assets` 使用 `multipart/form-data` 的 `file` 字段，返回本站素材 ID。`GET /v1/video/assets` 列举自己的素材，`DELETE /v1/video/assets/{id}` 删除未引用素材。

## 任务与资金安全

- 在一个数据库事务中创建任务并冻结钱包余额/Key 预算；批量最多 40 个镜头，全部验证后一起入库。余额不足整批回滚，不接受半批。
- `Idempotency-Key` 与请求哈希绑定；网络异常重试同一内容必须沿用原编号。相同编号不同内容返回冲突。
- 钱包冻结和 Key 额度预留都在提交上游前完成；明确成功才结算。明确失败或取消尚未提交的排队任务，会退回冻结余额和预留额度。
- 工作进程通过 PostgreSQL 租约、行锁和短期 advisory lock 协调，各应用实例共用账号并发上限（同账号绑定多个渠道时采用开放渠道中最小的并发配置）。关网页不停止队列，重启后继续查询已存的上游任务 ID。
- 创建请求只发一次：连接中断、5xx 或缺少 ID 时进入 `needs_review`，不盲目重发或退款。已发送上游的任务不能通过本地“取消排队”按钮退款。
- 24 小时无结果、未知状态或成功却无视频也进入待核对状态。管理员核实后可绑定/更正上游任务 ID 继续查询，或填写依据确认退款。人工操作进入现有面板审计链。
- 查询已创建任务不要求当前钱包仍有余额。API Key 入口按同用户、同 Key 隔离；登录后的工作台可查自己所有视频任务。
- 视频用量目前在视频历史中单独展示；这里的余额与 Key 额度变化不会伪装成文本 Token 用量。

## API

这是 LaneAI 异步任务适配，**不是 OpenAI Videos `/v1/videos` 协议**。

```sh
curl "$BASE_URL/v1/task/submit" \
  -H "Authorization: Bearer $SUB2API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: client-unique-request-0001" \
  -d '{"model":"MiniMax-H3","input":{"prompt":"晨光中的海浪","duration":4,"resolution":"768p","aspect_ratio":"16:9","generate_audio":false}}'

curl "$BASE_URL/v1/task/$TASK_ID" \
  -H "Authorization: Bearer $SUB2API_KEY"
```

外部 API 不需要传 `key_id`，由认证密钥确定。参考素材数组使用本工作台素材库 ID，而不是任意远程 URL。任务返回本站 ID 与状态 `pending / submitting / queued / in_progress / completed / failed / needs_review`，成功后从 `outputs` 读取 HTTPS 视频地址。

面板接口在 `/api/v1/video-studio`，使用原有登录 JWT：`options`、`quote`、`tasks`、`tasks/batch`、`projects`、`plan`、`assets`。`settings`、`reviews` 和人工结算仅管理员可用。

## 验证与部署

- `go test -race ./internal/videostudio`：纯单元测试默认运行；PostgreSQL 场景需设置 `VIDEO_TEST_DSN`，测试自动创建/删除独立 schema，不能使用权限受限的生产账号。
- PostgreSQL 场景覆盖并发幂等、重复结算、失败退款、事务回滚、批量原子性、任务归属、进程恢复、提交结果不明、账号并发和人工核对。
- 前端：类型检查、定价单测、ESLint；浏览器模拟接口覆盖单次确认、剧本拆分、批量提交及手机宽度布局。
- 部署前备份数据库，确认新迁移 `239_video_studio.sql` 没有与分支后续迁移重号，编译前端和后端。升级时只增加独立视频表和 `api_keys.video_reserved`，不修改既有文本模型价格。
- 上传需要反向代理允许至少 31MB 请求体（`/v1/video/assets` 与面板素材上传）；视频本体仍直接由上游生成与提供。
- 默认 CSP 新增 HTTPS 媒体播放许可。若部署自定义 CSP，需要相应设置 `media-src 'self' blob: https:`，否则浏览器可能无法播放外部视频。
- 回退旧程序前先关闭新视频提交并处理所有未结算任务。不可直接删除新表或清零冻结金额；旧程序不会替视频任务继续结算。
