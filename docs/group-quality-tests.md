# 渠道状态鹈鹕检测

管理入口：渠道管理 → 降智检测（`/admin/channels/quality-tests`）。点击“新增检测渠道”，选择渠道状态 V1 的监控项；复用系统的表格、选择器和弹窗组件。

检测对象是 `channel_monitors.id`，使用该监控项保存的端点、加密 API Key、API 模式和额外请求头。不会从账号池随机选择账号。可选择已启用的 OpenAI 模型监控项（排除仅额度监控）；检测模型固定为 `gpt-6-astra` / `gpt-6.1-sol`，不会改变已有健康监控主模型或附加模型。上游是否支持模型由实际检测请求确认，失败不会自动重试。密钥仅在服务端实际发起检测时解密，不返回前端。

默认客户权限为 hidden，自动检测关闭。可按渠道开放结果查看或手动检测；开放后入口在对应 V1 状态卡片上。V2 是分组被动指标，不按名称推测与 V1 监控项的关系。

弹窗左侧显示模型与该模型最近 5 次检测，右侧显示选中结果的 HTML/SVG 动画、耗时、生成长度和 token 用量，可查看/复制源码。预览使用不透明来源 sandbox iframe 与禁止网络访问的 CSP。

检测发送固定鹈鹕动画提示词，不自动判定“降智”或改变渠道健康状态。模型请求会消耗所选监控 Key 的上游额度；需要管理员人工比较结果。

开启自动检测后，每个选择的模型分别按周期调用。周期默认 10 分钟，允许 10 分钟至一年，提供 30 分钟、1 小时等快捷选项。保存后等待周期才首次调用，完成后再等待周期，不补跑历史任务。全站最多一个检测任务，单次最长 10 分钟，默认冷却 10 分钟。请求接收上游 SSE，输出上限 32768 token，分别支持 Chat 与 Responses，兼容返回 JSON 的上游；只有完整正文才能成为作品，不将思考转换为 HTML。界面实时显示生成耗时，关闭弹窗不终止生成。任务截止时间为 11 分钟，留一分钟落库余量。

检测窗口最大宽 1440px、高度为 90dvh；左侧模型与历史独立滚动，右侧动画占满剩余空间，手机视图可纵向滚动。

迁移 243 将当前配置和未来计划中的 6-sol 更新为 6.1-sol，旧 6-sol 检测历史保留，不修改用户、余额或普通网关的 Responses 兜底。

新增迁移 `242_channel_quality_tests.sql` 创建独立的配置、任务和计划表。旧 group_quality 表和历史保留，旧分组检测调度器不再运行；不会自动按名称将旧分组配置映射到监控项。新配置初始为空，避免未经选择就调用渠道额度。

后台不运行浏览器，不在生产服务器构建。部署使用 GitHub Actions 镜像，仅替换 sub2api 应用服务；数据库迁移随应用启动执行。
